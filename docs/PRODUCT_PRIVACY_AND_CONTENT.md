## I1 建議核定的第一版規則

### 位置精度

保留「有效登入者可看原座標」的既有確認。訪客採固定 0.01 度格網中心，運算為 `(floor(value * 100) + 0.5) / 100`；台灣約一公里量級，並非固定一公里半徑，不能宣稱匿名化。明示 `APPROXIMATE`／`EXACT`，地圖上概略點標示為格網概略位置，不能使用精確圖釘語意。

同一格網回應穩定，不因查詢人或時間增加隨機位移；可避免重複查詢平均值還原原點，但事件時間、暱稱及長期軌跡仍有重新識別風險。不要以更多小數位呈現不存在的精度。新增位置必須由使用者確認，不因開啟頁面直接蒐集裝置定位；瀏覽地圖不等於留下自身軌跡。

### 備註與照片可見性

建議訪客持續取得 `notes=null`、`photoUrl=null`。第一版不提供公開照片／備註的自行切換按鈕。

**待核准的收斂提案**：備註及新上傳照片只供紀錄本人讀取；其他登入者保留既有的精確位置、事件時間、暱稱及動物關聯。這會收窄現行「所有登入者可讀完整備註／照片連結」行為，屬明確授權變更，核准後才實作與更新 API 契約。未核准前維持現行程式，並不得稱內容已具本人私密性。

動物名稱、說明及暱稱仍公開。UI 提示不填門牌、電話、真名、住址或可辨識照顧者的資訊；輸入長度與 HTML escaping 不能替代內容治理。不得宣稱已自動識別或移除所有敏感文字。

### 動物關聯

建議紀錄可選現有動物或保留未辨識（`animalId=null`）；新增動物是獨立人工操作。選取時顯示種類與特徵，要求使用者確認，不按距離或照片自動關聯。指定不存在的動物回傳 404。錯誤關聯由紀錄本人透過修改改成另一既有動物或未辨識；不修改其他人的紀錄，不連動重寫動物歷史。

第一版不提供動物合併、拆分、跨會員批次重關聯或「已確認同一隻」保證。下一期另立活動區域推估、自動辨識／候選推薦與人工合併治理工作包，先評估誤判、追蹤風險及可回復機制。

## I4 建議核定的照片流程

建議第一版採應用程式管理的私有儲存；開發／單機 staging 可用 checkout 外的持久目錄，Production 是否改用私有 object storage 另依部署與備份能力決定。不採公開 bucket，不承諾特定供應商免費額度或永久免費。

1. 只有有效登入者可替自己的紀錄上傳；每筆最多一張，限制原始檔 5 MiB、解碼像素 12 megapixels。只接受可驗證的 JPEG／PNG，拒絕 SVG、GIF、動畫、未知格式及解碼失敗內容；不信任副檔名或 client Content-Type。
2. 先限流、限制 request body 與解碼資源，再在隔離暫存區實際解碼；以維護中的影像處理工具轉成最大長邊 1600px JPEG。依 EXIF orientation 旋正後重新編碼，丟棄 EXIF、GPS、原檔名及其他 metadata，只保留必要像素。拒絕超額解壓／像素資料，處理逾時回收暫存。
3. 成功版本使用不可猜測 storage key；資料庫保存內部照片 id、紀錄 owner、版本及狀態，不回傳磁碟路徑。處理成功前不可讀，失敗不覆蓋前一張可用照片；處理完清除原檔。
4. 透過需要每次授權檢查的同源 endpoint 串流照片；`Cache-Control: private, no-store`、`X-Content-Type-Options: nosniff`，無公開 CDN。猜到照片 id 或持有他人 URL 仍不能讀；本人登出／刪除後不能再取得。第一版避免 signed URL 到期前無法撤回的問題。
5. 首次上傳提示：使用者有權提供照片、避免人臉／車牌／私人住址，照片不向訪客公開。去 EXIF 不能移除畫面中的地址或辨識資訊，不宣稱自動去識別。

現有 `photoUrl` 是外部 HTTPS 連結，外部站點可追蹤 IP、外連內容可變且可能公開。新流程不得自動下載既有 URL（避免 SSRF 與未授權複製），不得將它當作私有照片完成證據；建議 UI 不自動嵌入舊外連，允許本人移除或重新上傳。舊連結是否隱藏／停止回傳須與上述可見性變更一起核准，不能偷偷刪除既有資料。

## I4 建議核定的修改／刪除矩陣

以下皆為尚未實作的提案；不因定義 endpoint 就視為已授權或驗證完成。

| 操作 | 訪客 | 非本人登入者 | 本人 | 第一版規則 |
| --- | --- | --- | --- | --- |
| 修改紀錄 | 401 | 404 | 允許 | 可修改 kind、observedAt、座標、notes、animalId；沿用新增驗證，不能改 owner／created_at |
| 修改／移除照片 | 401 | 404 | 允許 | 一張取代；舊版本停止對外服務並排入清除 |
| 刪除紀錄 | 401 | 404 | 允許 | 二次確認後立即自所有列表、地圖、本人歷史與照片讀取消失 |
| 修改／刪除動物主檔 | 不提供 | 不提供 | 不提供 | 本人建檔也不得影響他人關聯；下一期另定治理 |
| 管理員讀取／代改／復原 | 不提供 | 不提供 | 不適用 | 現行沒有 admin role，不虛構後台權限 |

使用版本欄位或 ETag 避免兩次編輯互相覆蓋，過期版本回傳 409；本人畫面需重新讀取再確認，不能無聲覆蓋。事件時間不可未來，座標合法，關聯必須存在，字數限制沿用 API。編輯不能修改他人資料，即使 request body 偽造 memberId 亦無效。

刪除先以 tombstone 立即阻止讀取，讓背景清除可重試；active storage 的照片及敏感欄位建議 24 小時內清除。最小稽核只保留紀錄 id、操作者 id、時間、動作與版本，建議保存 30 天；不複製備註、原座標、照片或完整 request body。稽核是否具法律保存義務尚未評估，不視為法規結論。

備份採加密且限制存取，建議保留 7 天、到期自動輪替；刪除不宣稱能立即改寫不可變備份。保留最小 deletion ledger，至少涵蓋備份生命週期；復原演練須先重播刪除清單並檢查照片清除，再開放服務。前述 24 小時／30 天／7 天均為待核准期限，採用前須驗證實際排程、故障告警及還原能力。
