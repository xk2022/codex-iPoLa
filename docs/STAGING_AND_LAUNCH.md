# IPoLa 手機閉環與分階段上線方案

查核日期：2026-11-13。狀態：I3 驗收規格與 I5 建議草案，尚未部署或驗收上線。

## 已查核現況與範圍

依 [後端說明](../backend/README.md)、[既有設計](backend-decisions.md)、`ApiController.java`、`ApiService.java` 與 `SecurityConfig.java`：目前只有 Java 後端，沒有前端；已具備註冊、登入、登出、目前會員、動物建立／列表、目擊／餵養新增與列表、會員紀錄列表。尚無上傳、修改／刪除、帳號復原、限流或管理員處理 API。列表採 `limit/offset`，不是 `page/size`，本期前端應相容現有介面。

訪客得到概略座標，所有有效登入者目前都能取得精確座標、備註與照片連結；登入並不等同照顧者身分經驗證。動物名稱、外觀與暱稱仍公開。公開註冊的服務若直接上線，任何人可自行註冊查看精確位置，不能以「需登入」宣稱已完成敏感位置保護。產品規則須先定案，見 [隱私與內容草案](PRODUCT_PRIVACY_AND_CONTENT.md)。

建議順序：I1／I4 規則決策 → I2 真實 MySQL 證據 → I3 手機閉環 → I4 必要功能 → 私有 staging 驗收 → 經核准才安排正式發布。活動區域推估、自動辨識／合併屬下一期。

## I3 手機版最小閉環

建議採同源部署的 TypeScript 前端，避免為第一版額外引入跨站認證。框架、樣式與地圖套件選擇先提出依賴清單及授權／資料來源；專案規則要求新增依賴先核准。本文件未選定或安裝依賴。地圖服務不得將精確座標送至第三方分析、搜尋或追蹤服務；瓦片商的使用政策、配額、署名與隱私須查核，不假設公共瓦片可無限制使用。

| 流程 | 介面與 API | 可驗收結果 |
| --- | --- | --- |
| 登入／登出 | `POST /api/auth/login`、`GET /api/auth/me`、`POST /api/auth/logout` | 成功後辨識本人；錯誤密碼顯示可理解訊息；過期／無效 token 清除狀態並要求重新登入；登出後不能保留精確位置畫面或快取 |
| 地圖／列表 | `GET /api/observations?limit=…&offset=…`；動物列表可輔助篩選 | 使用相同資料切換視圖；標示概略／精確精度，概略點不是動物真實位置；只顯示歷史點，不畫推估活動範圍；下一頁不重複或漏掉同時間資料 |
| 新增目擊／餵養 | `POST /api/observations`；需要時 `POST /api/animals` | 可選兩種類型、事件時間、位置、備註及經定案的動物關聯；未辨識可不建動物；定位被拒可手動選點；確認提交後避免連點重送；失敗保留表單 |
| 本人紀錄 | 先由 `/api/auth/me` 取得本人 ID，再呼叫 `/api/members/{id}/observations` | 新增後能找到該筆紀錄；類型、時間與關聯一致；不能靠前端「本人」標籤取代後端寫入權限檢查 |

手機驗收使用至少 360px、390px 寬度，以及桌面回歸；鍵盤可操作，欄位有標籤、錯誤提示與載入／空資料／失敗狀態。以真實 API 測試一次登入→目擊→本人紀錄、一次餵養→本人紀錄、定位拒絕、網路失敗、分頁、登出與失效 token。瀏覽器測試不得保存 token、真實個資或敏感座標到公開截圖／錄影。

目前 API 沒有單筆紀錄查詢或 idempotency key；前端不能宣稱網路逾時後重送必定不重複。第一版先禁止送出中連點，逾時提示查本人紀錄確認再重試；更完整冪等機制另評估。

## 開放對象與部署路線

建議第一站採「指定測試者、合成資料、網路層限制存取」的私有 staging。staging 的網路保護屬新增安全設定，需核准後實施；不得把目前公開註冊程式部署到無保護網址後稱為封閉測試。正式開放對象未決，暫不安排公開發布日期。

| 路線 | 適用與成本邊界 | 必須處理 |
| --- | --- | --- |
| 現有電腦／雲端開發環境內 Docker MySQL 與應用 | 適合開發、重現與 CI 前置；可不新增主機費，仍使用既有設備與網路 | 非公開正式服務、環境可能休眠或重置，不能當持久備份 |
| GitHub Actions MySQL service | 適合 migration、核心 API 與權限／分頁驗證 | 依儲存庫可見性、方案與剩餘配額決定費用；私人庫不保證無限免費；先查配額、不啟用付費超額；CI artifacts 不是資料庫備份 |
| 免費額度 PaaS／託管 DB／物件儲存組合 | 適合短期展示或小量私有 staging 的候選 | 必須當下查官方定價、區域、Java/MySQL 支援、休眠、儲存持久性、連線數、出站費、保留期及信用卡要求；不得保證永久免費 |
| 小型 VM ＋ MySQL ＋ 私有照片儲存 | 元件相容、部署較直接；可能需付費 | 維運、修補、憑證、監控、容量與異地備份責任由專案負擔；新增付費資源須核准 |

保留既有 MySQL 目標可避免為免費供應商更換資料庫而擴大改造。若預算必須為零，先採現有設備與配額內 CI 完成 I2/I3；公網常駐可用性、網域、信件與異地備份成本須另確認。本文件未建立帳號、資源或訂閱，也未查核任何供應商當日價格。

## I5 安全與營運提案（需核准後實作）

| 項目 | 第一版具體提案 | 必要測試與證據 |
| --- | --- | --- |
| 帳號復原 | 驗證信箱控制權後，發送短效、單次、高熵復原 token；資料庫只存雜湊；回應不洩漏帳號存在性；成功重設後撤銷既有登入 token；復原網址固定可信網域、不接受任意 Host；不得將 token 寫入日誌 | 存在／不存在帳號相同對外回應；過期、重放、錯誤 token、並發使用；重設後舊登入失效；寄信失敗可追蹤且不外洩憑證 |
| 限流 | 登入與復原同時依帳號識別與來源 IP 限制；註冊、寫入與照片另設配額；超限回 `429`／`Retry-After`；採漸進退避，避免永久鎖帳成為阻斷工具 | 提案起始值：登入每帳號 10 次／15 分鐘、每 IP 60 次／15 分鐘；復原每帳號 3 次／小時、每 IP 20 次／小時。需依共享網路與實測調整；測正常負載、攻擊、重啟與多實例一致性；代理來源標頭只信任已配置代理 |
| 備份與還原 | MySQL 每日一致性備份，加照片／稽核所需索引與版本；加密保存於不同故障域；以獨立權限保護；第一版提案採 7 天輪替，與產品刪除政策一致；較長期備份另期評估並核准 | 封閉測試目標 RPO 24 小時、RTO 4 小時，屬待核准目標；空白隔離環境還原後驗證 migration、筆數、關聯、登入與代表 API；記錄備份時間、checksum、還原耗時；刪除清單（deletion ledger）必須涵蓋所有仍可還原的備份生命週期，還原後先重放刪除清單，驗證已刪資料與照片不會復活，才允許對外提供服務 |
| 濫用處理 | 公開簡明規範、檢舉入口與處理負責人；收集紀錄 ID、原因與必要證據；先隱藏危害內容，再依審核決策停權；保留有限期稽核及申訴流程 | 測惡意檢舉、重複檢舉、他人操作、管理員越權；內容下架同步照片可見性與快取；未建立管理員角色前不得用共用帳密處理 |
| 日誌與監控 | 記錄錯誤率、延遲、資料庫／磁碟容量、限流與備份結果；日誌排除 token、密碼、備註、照片內容與精確座標 | 測錯誤頁與反向代理存取日誌；警示有實際接收者、處置說明與維護窗口；未配置警示不得宣稱有人全天監看 |

上列數字是可審閱預設提案，不是已核准 SLA、正式政策或已實作能力。註冊開放方式、信箱驗證、復原與授權變更必須依專案 `AGENTS.md` 核准；通知寄送與新信件服務也須確認目的與費用。封閉測試若暫無自助復原，可明示尚未提供並僅使用可重建的測試帳號；不得把這個限制帶入公開正式服務。

## Staging 驗收門檻與發布紀錄

每項門檻保留主要 Issue、commit SHA、執行日期、測試命令／結果與 CI run/artifact 連結。缺失項目標示待辦或受阻，不能用檢核表代替實證。

- I1／I4 可見性與本人操作規則已確認，實作及測試一致；所有公開入口、錯誤與照片取得路徑不外洩精確位置或私人內容。
- I2 真實 MySQL 空庫 migration、重啟／再次 migration、核心 HTTP API、權限與分頁均通過；H2 回歸維持通過。
- I3 手機閉環與失敗情境通過；若包含照片／修正，I4 的 MIME、大小、去中繼資訊、本人與他人邊界同步驗收。
- 部署採固定 artifact，記錄設定名稱與版本，不記錄值；HTTPS、可信代理、資料庫網路隔離與最小權限確認；staging 只用合成資料且不得沿用正式憑證。
- 實際完成一次備份→隔離還原→核心 API 驗證；演練應用回滾。資料庫優先前進修復，不回寫或改動已套用 migration；不能以直接刪庫當回滾。
- 正式對象、支援／檢舉窗口、隱私告知、資料保留與刪除方式、容量與成本上限、帳號復原及限流驗收完成。
- 人工批准正式環境、網址與開放對象後才發布；記錄發布者、SHA、備份參考、檢查結果及回滾觸發條件；異常時限制存取／回退應用並保護資料。

目前以上為驗收規格，沒有 staging 網址、部署、MySQL CI run、備份還原或手機 E2E 成功證據。發布日期待條件達成再排定。

## 執行總管需集中確認的決策

1. 是否先限定指定測試者，並保留「任何登入會員可看精確位置」的既有規則？若需改為受信任照顧者，屬授權政策變更，先核准再開發。
2. I1／I4 內容可見性、私有照片儲存、本人修改／刪除與保留期決策，以產品規則文件為單一來源。
3. 前端新增依賴與地圖供應商清單、零新增費用優先或可接受的費用上限；取得核准後實作 I3。
4. 公開發布前指定營運／濫用處理與備份責任人，確認信件／復原方式、RPO/RTO、正式環境與發布授權。

決策未回覆時可繼續：本機／CI MySQL 驗證準備、前端介面與測試設計、部署與復原 runbook 草稿。不可因此自行變更安全政策、建立付費資源或公開部署。
